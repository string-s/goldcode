# 已确认的比赛约束

以下信息由赛事方答复确认，作为 Wolf Agent 的设计约束。

## 身份与数据

- 对手 ID 稳定，可以作为跨局对手画像的主键。
- 参赛 SDK 就是赛事方提供的 Python/JavaScript 压缩包。
- Agent 只能连接自己被分配的比赛，不能订阅其他桌的 WebSocket 数据。
- 运行环境在本地，可以读写本地文件。

因此可以将对手画像持久化到本地，但只能使用本队真实参与比赛时获得的数据。

## 进程与策略更新

- 自由赛阶段可以更新代码和重启进程。
- 淘汰赛阶段基本不能重启，掉线会带来直接淘汰风险。
- 进入 16 强前会提供约 10 分钟策略调整时间，届时可以修改策略并重新连接。

工程含义：

1. 自由赛可以进行“复盘 → 修改 → 测试 → 重启”的外循环。
2. 淘汰赛开始前必须冻结策略版本和依赖，比赛中不做热更新。
3. 16 强调整窗口使用已经离线验证过的候选版本，不能现场无保护地让 LLM 重写代码。
4. 每次上线保留上一稳定版本和明确的回滚方式。

## 地图

地图是否每局变化尚未得到明确结论。Agent 不依赖固定地图：每次 `startGame` 都解析
并缓存服务端下发的 `data.map`，后续帧使用本局缓存。即使未来确认地图固定，也继续
保留这条路径，避免规则或训练环境调整造成硬编码失效。

## 尚需确认

- 正式局分最终采用 `4/3/2/1` 还是旧资料中的 `3/2/1/0`。
- 自由赛收到结算后，允许延迟多久再发送 `readyForNextMatch`。
- 16 强调整窗口的准确开始、结束信号与重新连接流程。
